## [2026-09-17] — Codex

Проведена первая проверка с тестовой 1С:

- Прямой `POST /prtr_driver/events` в 1С с XML-событием дошёл транспортно:
  HTTP 200, XML-ответ 1С получен. На первом sample GUID 1С вернула
  бизнес-отказ по неизвестному водителю.
- Сквозная проверка через gateway прошла: Android JSON → gateway → XML в 1С →
  XML-ответ 1С → JSON для Android. Gateway вернул поштучный JSON-результат.
- Добавлена поддержка Basic Auth для исходящих запросов gateway → 1С:
  `ONE_C_USERNAME`, `ONE_C_PASSWORD`.
- Sample GUID события в `docs/samples/*` обновлён после реального прогона,
  чтобы следующие ручные проверки не упирались в дедупликацию 1С.

Зафиксировано решение по стеку: Go + Python. Создан backend-каркас:

- `backend/gateway` — Go-шлюз с healthcheck, graceful shutdown, таймаутами,
  приёмом XML-разнарядки, регистрацией FCM-токена телефона, выдачей актуальной
  разнарядки мобильному приложению и форвардингом пачки событий в 1С.
- Добавлен технический delivery-cache в контейнерном volume: XML разнарядок и
  FCM-токены устройств. Это не бизнес-истина; 1С остаётся источником правды.
- Добавлен FCM HTTP v1 sender через service account JSON; если credentials не
  заданы, push только логируется для локальной стыковки.
- `tools/python/mock_1c.py` — локальный мок эндпоинта `POST /prtr_driver/events`,
  возвращает поштучный XML-ответ по событиям.
- Добавлены `Dockerfile`, `docker-compose.yml`, `.env.example` под серверный
  запуск за Traefik в external-сети `edge`.
- Добавлены request id, логирование HTTP status/bytes и `GET /readyz` для
  диагностики конфигурации 1С/FCM.
- Мобильный API переведён на JSON: регистрация устройства, получение
  разнарядки, отправка событий. Шлюз сам конвертирует JSON-события Android в
  XML для 1С и XML-ответ 1С обратно в JSON с поштучным `accepted`.
- Для стыковки оставлены диагностические XML-ручки выдачи исходной разнарядки:
  `/api/mobile/assignments/current/xml` и `/api/mobile/assignments/{id}/xml`.
- Добавлены сэмплы `docs/samples/assignment.xml`,
  `docs/samples/mobile-events.json` и чеклист `docs/integration-checklist.md`
  для проверки обмена 1С → шлюз → Android JSON и Android JSON → шлюз → 1С.
- Повтор той же версии разнарядки теперь снова проходит push-доставку; только
  версия ниже сохранённой игнорируется. Это важно, если 1С ретраит после
  временной ошибки FCM.
- Добавлены базовые Go-тесты валидатора событий на уровни разнарядка/ездка,
  обязательный комментарий для `Срыв`, отказ от кривого ISO-8601 смещения и
  стык JSON/XML на событиях и разнарядках.

Android-клиент ещё не начат. `go test ./...` проходит. `docker compose build`
не запускался: Docker CLI отсутствует в текущем окружении.

## [2026-09-17] — Claude

Инициализация проекта. Из длинного обсуждения архитектуры с автором и переписки
с 1С-командой собраны:

- `AGENTS.md` — общие правила, доменный словарь, инварианты обмена, границы проекта
- `docs/architecture.md` — полный контракт: XML-схемы разнарядки и событий, статусная
  модель, эталонная последовательность событий за смену, открытые вопросы

Ключевые решения, зафиксированные на этот момент:

- Backend пишется на Go (решение о переносе на Python не принято, стек может измениться)
- Прицеп принадлежит ездке, не машине — может меняться между рейсами
- Событие `ПринялЗадание` исключено из контракта
- Клиентский GUID событий — обязателен с первого дня, не опция
- Автосинхронизация (WorkManager) и передача рейса другому водителю — на дополнительном этапе

Открыто: поведение ездки без прицепа (пустой тег vs отсутствие элемента), реалистичность
плановых времён в тестовых данных 1С — влияет на то, имеет ли смысл индикация
«успевает / не успевает» на данном этапе.
