# АРМ водителя для iPhone: план веб-приложения

Решение: веб-приложение на том же Go-шлюзе и JSON API, которое водитель добавляет
на экран «Домой». XML-контракт 1С не меняется. Первая цель — iOS 17+; на
iOS 16.4–16.x уведомления работают, но поведение локального хранилища нужно
проверять отдельно на устройстве.

## Контуры и доступ

- У test3 и боевой базы разные экземпляры шлюза, URL, файлы сессий и локальные
  хранилища браузера. Веб-данные всегда привязаны к контуру и GUID водителя.
- Общий `MOBILE_TOKEN` Android не отправляется в JavaScript. Сотрудник,
  выдающий телефон, создаёт одноразовый код привязки через защищённый endpoint
  шлюза. После ввода кода браузер получает ограниченную сессию в cookie
  `HttpOnly`, `Secure`, `SameSite=Strict`. Сервер проверяет GUID водителя для
  каждого чтения и записи.
- Сессии и коды — технические данные доступа, не бизнес-истина. Разнарядки
  по-прежнему приходят только из 1С.

## Сценарий водителя

1. Открыть `/web/`, добавить на экран «Домой», привязать кодом, включить
   уведомления (системный запрос после нажатия кнопки).
   Внешний вид повторяет Android Compose: белый фон, фирменный логотип,
   верхняя строка разнарядки, четыре нижние вкладки, серые карточки и
   чёрные/оранжевые кнопки.
2. Список разнарядок, включая полученные с вечера, заменённые и отменённые.
   Ознакомление с маршрутом, начало смены только в дату выезда и после ключей.
3. Ездки по `order`, действия только по GUID: прибытие на погрузку, загрузка,
   прибытие на разгрузку, разгрузка, срыв с причиной. Порядок и ограничения
   соответствуют Android/контракту v1.5.
4. Камера для обязательных фото, геометка по нажатию кнопки, локальная очередь
   событий и фото. GUID и время фиксируются до сети; очищаются только
   поштучно подтверждённые 1С записи. Очередь и ошибка отправки видны водителю.
5. В конце — ожидание приёма ключей и подтверждения медика; мобильного
   `ОкончаниеСмены` нет.

## Проверка перед публикацией

- Локальные тесты безопасности сессий, частичного отказа 1С и замены
  разнарядки; браузерная проверка интерфейса.
- На реальном iPhone: установка на экран «Домой», Web Push, камера, геометка,
  офлайн-очередь после закрытия и открытия приложения. Только после этого
  публикация. Продакшен Android и шлюз во время разработки не меняются.
